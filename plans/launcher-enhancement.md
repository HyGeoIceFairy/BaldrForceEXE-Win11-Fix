# 启动器增强与更新发布计划

## 目标与边界

- 暂定版本 1.1.0；实施前核对远端标签与 Releases，必要时顺延版本，不覆盖既有发布。
- 使用原生 Windows 中文启动面板，保持便携分发，不新增大型运行库。
- 保留原有音效别名和进程内兼容修复，不修改磁盘上的游戏程序，不读取或改写用户存档。
- 游戏安装位置已找到：[本机游戏目录](../../Game/Baldr%20Force%20Exe)。只读取与验证相关的内容；外部写入如需审批必须正常申请。
- 当前阶段完成方案，进入实现前由模式切换确认方案。

## 本次功能范围

| 功能 | 行为与验收要求 |
| --- | --- |
| 显示模式 | 普通窗口、全屏、无边框全屏；无边框仅在兼容性实测通过后作为稳定选项 |
| 窗口尺寸 | 原始大小、800×600、960×720、1024×768、1280×960、自定义；指游戏客户区显示尺寸，不宣称提高资源精度 |
| 尺寸校验 | 拒绝空值、非法输入、零、负数和溢出；结合当前显示器工作区与 DPI 检查，超出可用范围时说明并给出可用尺寸，不静默变更用户选择 |
| 缩放 | 默认保持游戏原始比例，可选拉伸；清晰与平滑缩放需验证实际 DirectDraw 输出效果 |
| 常用选项 | 窗口居中、鼠标限制、垂直同步；模式不适用的设置禁用并说明 |
| 快速启动 | 记住设置，可选择以后直接进入游戏；提供明确的设置命令入口与按住 Shift 启动打开设置的恢复途径 |
| 工具入口 | 打开游戏目录、使用指南、项目发布页；不自动联网检查或下载更新 |
| 诊断 | 文件与版本检查、兼容层检查、阶段化错误信息、本地日志和复制诊断摘要；不采集存档、不上传、不记录无关私人路径 |
| 恢复 | 恢复推荐显示设置只影响受管理选项；明确原始配置备份位置，不删除用户文件 |

暂不包含存档恢复、自动更新器、游戏修改器、全局快捷键和新输入兼容层。显示设置原则上在下一次启动生效；运行中切换快捷键不作为本次承诺。

## 实现顺序与技术约束

1. **建立基线。** 检查工作区变更、Git 远端、版本、编译器和发布认证；记录旧启动器及兼容层摘要，确认本机游戏匹配已支持版本。不读取凭据内容，不丢弃用户修改。
2. **验证显示控制。** 根据随附配置注释及 dgVoodoo2 官方说明确认强制显示模式、窗口属性和输出缩放的语义。分别验证普通窗口、全屏和无边框，以及窗口尺寸和输入坐标。不得假设三维强制渲染分辨率对本游戏的二维输出同样有效；若需要调整目标窗口客户区，只采用经验证的最小 Windows 窗口操作，不扩大内存补丁或新增注入模块。
3. **分离职责。** 从[现有入口](../src/Start-BaldrForce.c:208)分离配置处理、启动面板和原有兼容启动流程。避免为每个选项建立碎片模块；将可测试的配置转换与进程、文件系统副作用隔离。
4. **安全管理配置。** 引入启动器独立设置，首次无设置时导入可识别的旧显示选项；遇到未知或高级配置保留原内容并提示，不静默覆盖。面板打开与取消不写文件；启动或显式保存才提交经过校验的受管理项。
5. **可恢复写入。** 修改前保留原始兼容层配置备份，使用同目录临时文件、校验与原子替换。保留未知键、其他章节、注释和合理编码；正确区分不同章节内的同名键。写入失败不得启动带有部分设置的游戏，备份不可被后续保存静默覆盖。恢复默认只重置受管理项。
6. **原生界面。** 简体中文、合理 DPI 缩放、键盘 Tab 顺序、模式与尺寸联动；启动期间显示状态并防重复点击，失败后回到可修改状态。无启动参数时默认显示面板，启用快速启动后仍能绕过该偏好进入设置；测试启动参数错误的行为。
7. **保持兼容安全。** 保留版本和地址特征校验、超时、仅终止自身创建的失败进程以及线程与句柄清理。在暂停目标线程后、写入前再次核对补丁字节。按安装路径识别重复游戏实例，游戏运行期间禁止修改其显示配置；不终止已有游戏实例。
8. **便捷与诊断。** 实现目录／指南／发布页入口、设置恢复和不含游戏数据的诊断信息。未完成自检也应能打开面板查看错误；项目目录没有游戏时可以测试面板，但必须明确禁用实际启动。

## 验证要求

- 自动化测试覆盖：默认值、旧配置迁移、无效输入、不同换行与编码、章节同名键、未知内容保留、缺失文件、只读文件、备份与替换失败、恢复默认、快速启动参数、重复实例。
- 将配置与打包测试接入现有构建工作流；若需运行 Windows 原生测试，增加 Windows 测试任务，不把交叉编译成功当成运行测试成功。
- 测试在工作区忽略的隔离目录中执行。必要游戏文件使用普通复制，先核对大小与空间；不对可写游戏文件使用硬链接，不搬移原目录，不引入用户存档。现有额外输入兼容组件不加入发布包。
- 实机矩阵包含：原补丁基线、三种显示模式、典型与自定义尺寸、比例与缩放、窗口居中、鼠标命中、失焦与切回、关闭与再次启动、标题菜单和战斗音效回归。
- 对 DPI／多显示器等条件区分实际测试与尚未覆盖，不虚报通过。无法自主完成的视觉或交互验收集中记录，必要时一次请求人工验证。
- 验证完成后保留可复核的测试摘要，发布资料不得包含本机游戏文件、存档、截图或私人路径。

## 构建与发布

1. 更新[本地构建](../scripts/build.ps1)与[持续集成](../.github/workflows/build.yml)，统一新增源码、资源和链接选项；检查架构、编译警告和运行依赖。继续保留可重复构建能力。
2. 修订[打包脚本](../scripts/package.ps1)：明确使用本次已验证产物，避免误发仓库旧二进制；保留显式白名单并检查 ZIP 实际条目与文件校验和。
3. 每次打包创建唯一暂存目录，禁止递归清空旧目录；已有目标包默认拒绝覆盖。写入或发布前检查最终解析路径，失败立即停止，不执行隐含清理。
4. 更新[说明](../README.md)、[使用指南](../docs/USER_GUIDE.zh-CN.txt)、[变更日志](../CHANGELOG.md)、[发布说明](../RELEASE_NOTES.md)、[构建文档](../BUILDING.md)和[发布流程](../PUBLISHING.md)；重点说明旧用户升级时如何避免覆盖自定义配置，以及新版设置的恢复途径。
5. 保持 dgVoodoo2 2.87.4 不变，除非实证表明必须升级；保留[第三方声明](../THIRD_PARTY_NOTICES.md)，不打包其他本机兼容层。
6. 构建、自动化测试、实机核心验收和白名单检查全部通过后，提交与推送本次相关变更，创建新标签和 GitHub Release，上传压缩包及 SHA-256 文件。
7. 若实机验证存在缺口，只发布明确说明缺口的预发布版，不替换稳定最新版。若认证或保护机制阻止发布，保留完整本地产物与发布说明并明确报告阻塞，不绕过安全机制。
8. 通过远端元数据与下载附件再次验证标签提交、版本、文件名、内容白名单与摘要一致，并提供最终 Release 地址。
